FoodBridge — System Engineering Report

Community Surplus Food Rescue & Hyper-Local Hunger Relief Network

1. Executive Summary & Problem Scope

FoodBridge is a multi-role, real-time cross-platform mobile system engineered using Flutter (Dart 3.x), Riverpod, and Supabase (PostgreSQL with Realtime WebSockets). The system provides an automated logistics pipeline resolving the urban food wastage paradox by connecting commercial kitchens, food relief shelters, and crowdsourced couriers.

Donor Kitchens

Commercial Donors

Hotels, restaurants, and caterers broadcast surplus meals with dietary tags and expiry windows in under 45 seconds.

Shelters & NGOs

Distribution Shelters

Verified orphanages and community pantries discover nearby donations on a live feed and claim them with 1 tap.

Volunteer Couriers

Mobility Fleet

Crowdsourced riders receive dispatch job cards with interactive turn-by-turn map navigation to deliver hot meals before spoilage.

2. Technical Architecture & Component Stack

System Layer Technology Selected Architectural Rationale
Mobile Client Framework Flutter 3.29+ / Dart 3.x (Impeller Backend) Native 60fps rendering, cross-platform code parity, reactive component model.
State Management Flutter Riverpod 2.4.9 Uni-directional reactive state, clean dependency injection, testability without BuildContext coupling.
Navigation Engine GoRouter 12.1.1 Declarative URL routing, smooth custom transitions, and guarded route redirection.
Database & Real-Time Supabase (PostgreSQL 15 + WebSocket Channels) Row-level filtering, sub-second broadcast of donation and job state transitions.
Mapping & Geolocation flutter_map 6.1.0, latlong2, geolocator 11.0.0 Hardware GPS coordinate tracking, OpenStreetMap vector rendering, route polyline overlay.
Local Storage shared_preferences 2.2.2 Persistent session authentication, role switching state, offline metadata.

5. Authentication & Session Architecture

The authentication subsystem is implemented in login_screen.dart and managed via userSessionProvider. It enforces session persistence across restarts with the following flow:
